01 / THE SECURITY GAP

Access control alone doesn't tell you what's inside a file.

Two files can be uploaded by the same authorized employee — but a public brochure and a customer-record spreadsheet should not receive the same treatment.

⌕

Content remains unseen

Traditional upload flows may validate a file without understanding whether it contains personal, financial or confidential information.

⌁

Different risks, same path

Public, internal and highly confidential files can require different protection controls even when they come from an authorized user.

⚑

Scans need action

Malware and sensitive-data findings are useful only when connected to a clear, consistent decision about what happens next.

02 / THE CORE WORKFLOW

One file. Four stages. A security decision.

DataShield's central contribution is the coordination of existing security mechanisms into a unified file-protection pipeline.

STAGE 01↧

Inspect

Receive and validate the file, scan for detectable malware, and inspect supported content for sensitive information.

STAGE 02⌘

Decide

Evaluate classification, scan findings, permissions and configured rules through a policy-based decision engine.

STAGE 03◇

Encrypt

Apply protection when required — such as authenticated encryption and restricted access — or quarantine/block unsafe files.

STAGE 04▣

Store

Send approved files to the designated storage location and preserve an audit record of the security decision.

05 / CONTENT CLASSIFICATION

Protection should follow sensitivity.

Classification gives the policy engine a structured way to select an appropriate level of protection.

Public

Information approved for public distribution. May proceed under the organization's standard policy.

Internal

Information intended for organizational use and not approved for unrestricted public sharing.

Confidential

Information requiring restricted access and additional confidentiality protection.

Highly Confidential

Highly sensitive information requiring stronger protection controls and carefully limited access.

06 / TECHNOLOGY & SECURITY DESIGN

Built by connecting proven components.

DataShield does not claim to invent malware scanning or encryption. Its contribution is integrating inspection outcomes with explainable policy decisions and file-handling actions.

Malware inspection

ClamAV is a possible scanning component for detecting known malicious content. A clean result does not guarantee that a file is harmless.

Authenticated encryption

AES-256-GCM is a possible choice for confidentiality and integrity protection when implemented with sound nonce and key-management practices.

Audit without data leakage

Record file identifiers, timestamps, findings and decisions — not unnecessary copies of sensitive file contents. Protect logs from unauthorized changes.

08 / VALIDATION PLAN

Security claims need measured evidence.

The prototype should be evaluated with controlled test files and documented results — not assumed performance claims.

TEST 01

Classification quality

Measure precision, recall and F1-score using labeled test files.

TEST 02

Malware scan outcomes

Test approved samples and record the scanner's results.

TEST 03

Policy enforcement

Verify each predefined case produces its expected action.

TEST 04

Encryption & integrity

Verify authorized decryption and file-integrity checks.

TEST 05

Access & audit

Test unauthorized access prevention and completeness of audit records.

TEST 06

Performance

Measure processing time and throughput across different file sizes.

Research principle: DataShield's contribution is the integration and implementation approach. Detection limitations, false positives and false negatives, key-management risks, and processing overhead must be acknowledged and evaluated.
